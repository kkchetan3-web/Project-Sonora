# Technical architecture

See [ARCHITECTURE.md](ARCHITECTURE.md) for the target design. Current local-first implementation uses Compose, SAF persisted read grants, a MediaController and a MediaSessionService hosting ExoPlayer. Local preferences store imported document URIs, favourites and a playback snapshot. Queue snapshots are local only; no network or user history collection is implemented. Treat these preferences as transitional, not a scalable database or secure catalogue model.

Target boundaries: playback service and persistence; local library repository; provider catalogue with explicit source rights and capabilities; search/index; playlists; opt-in recommendations; rights-aware downloads; licensed/user lyrics; optional authenticated social/AI services; settings and privacy. Use Room with schema migrations for durable data as scale increases, DataStore for settings, and WorkManager only for tasks that need durable scheduling. No external service should be required for local playback. Cross-device sync, sessions and AI require separate services, identity and threat models.
